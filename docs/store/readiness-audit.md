# Store readiness audit (T-STORE-01)

**App:** Demios Desktop 0.1.0, bundle id `io.demios.desktop`, `apps/desktop` (Tauri 2).
**Audited:** `main` at `d5f9463`, 2026-11-24, by W-store.
**Targets:** macOS direct download (Developer ID, hardened runtime, notarization), Microsoft Store (MSIX), signed direct Windows download as a fallback, Linux via Flathub. The Mac App Store is out of scope for now.
**Accounts:** none yet. This audit prepares; nothing was signed or submitted. No secrets, certificates or account ids belong in the repo.
**Listing:** the free app will be listed.

**Reference:** the app-store-compliance skill, pinned `ad76746e` (v2.5.1, licence OpenRoots ORA 2.3). It was read as reference data only. Its rules are written for iOS and Android, so for each finding we cite the closest rule file and say when a desktop-store rule comes from outside the skill. Rules marked *(verify)* come from general platform knowledge. Check them against the store's live documentation before acting on them.

## How the automated scan went

`app-store-compliance-guard.sh` (2,115 lines) was read in full before anyone tried to run it. Findings:

- **Reads:** it walks the target folder with `find` and `grep`. A copy of every text file goes into one temp buffer.
- **Writes:** only `mktemp` files (falling back to `/tmp/ascg.$$`). An `EXIT` trap removes them.
- **Network:** none.
- **External commands:** `python3`, for helpers inside the skill folder only: `scripts/deadline-checker.py` (reads `data/regulatory-deadlines.json`), the privacy-manifest validator (iOS only), and an inline reader for `.app-review-readiness.json`.
- **Sourcing:** line 12 sources `$HOOK_LOG` if it exists. `HOOK_LOG` is not taken from the environment. Line 10 hardcodes it to `$HOME/.claude/hooks/hook-log.sh`, so `env -u HOOK_LOG` has no effect. That file does not exist on this machine, so nothing would be sourced.
- **Hook mode:** reading stdin only happens when stdin is not a TTY and no directory argument is given. With a path argument and `</dev/null` it runs standalone.

Running it as briefed (`env -u HOOK_LOG bash …/app-store-compliance-guard.sh apps/desktop </dev/null`) was **refused by the session's permission classifier**. It was not retried or worked around, so **there is no scanner output in this audit**. Re-run it by hand, or grant the permission, to get the real output.

From reading the code, the expected result for `apps/desktop`:

- `Platforms. iOS=0 Android=0 Web=1` and `Frameworks. … Tauri=1`.
- The note "No src-tauri/gen/apple or gen/android folder".
- The web checks run. They would probably raise `WEB-LOCAL-STORAGE` [HIGH] for `ui/src/components/App.tsx:43,52`. That is a false positive: it stores a UI preference flag, not personal data.
- It then ends `NOT CHECKED … store checks did not run` with exit 1.

The guard has no macOS-desktop, MSIX or Flatpak checks. Everything below comes from the manual review, which the skill itself requires (SKILL.md Step 3).

### Data-collection declaration (for S-04, the store privacy forms and the Flathub metainfo)

- **Demios collects nothing.** No account, no analytics, no crash reporting, no Demios server. Settings and chats stay in a local SQLite file. Provider keys and MCP credentials are in the OS keychain (`dn-secrets`).
- **What the app contacts, always because the user started it:**
  - the BYOK provider the user configured (OpenAI, Anthropic, Gemini or a custom OpenAI-compatible URL), with chat content, under the user's own account and that provider's policy;
  - Hugging Face, to list and download models (model files are fetched straight from `huggingface.co` or an `HF_ENDPOINT` mirror);
  - MCP HTTP servers and their OAuth servers;
  - MCP stdio servers the user installed, which run locally and may reach the network on their own.
- **Later:** the update check, once T-STORE-08 lands, for direct downloads only.
- **Store forms:** the Microsoft Store privacy and data answers can say "no data collected by the developer". The policy must still describe these user-started third-party flows.

**What the Mac App Store would also need.** The App Sandbox is mandatory (2.4.5(i)). That breaks the core MCP model: a sandboxed app cannot run arbitrary user-installed programs such as `npx`, `uvx` or `docker` with their normal access. Children inherit the sandbox, and anything they run has to be inside the app bundle and signed. Code that MCP servers download would also conflict with 2.4.5(iv). The Tauri updater would have to be compiled out (2.4.5(vii)). File access would need security-scoped bookmarks for user-selected folders, and the Keychain needs access-group entitlements. On top of that: the full App Store Connect stack (privacy nutrition labels, the 5.1.2(i) consent modal before data goes to a third-party AI, age rating, DSA trader status, `ITSAppUsesNonExemptEncryption`, export compliance). A Mac App Store edition would realistically ship with **HTTP MCP servers only** plus bundled, signed tools. Treat it as a separate product flavour, not a re-packaging.
